## 六 V 暴露并已修复的工具问题

1. 公网地址检查在本机对所有域名误判为内网（解析器把域名映射到 198.18.0.0/15）。加 `BEACON_FETCH_IP_CHECK` 开关，关闭后仍阻断字面量内网地址。
2. 同一轮批量运行里抓取成功的文件没有被分析：改为抓取后重新规划。
3. 规则版本升级后旧分析被跳过：规划时比对规则版本。
4. HTML 提取器按行匹配对真实站点几乎无效：改为 DOM 关联，并发现页面中的 PDF/图片候选（`menu_not_in_html` 问题带候选链接）。
5. 人工无法在图片分析上新增问题与菜品：`PATCH /api/analyses/{id}` 支持 `issues[new]`、`items[new]`（必须带证据）。

## 七 未解决的问题

- Squarespace 站（Hanoi Pho、Sutton）菜单页正文无菜单；图片候选把菜品照片当菜单（Sutton 4 张全是照片），需按尺寸比例或 OCR 粗判过滤。
- 无视觉模型：图片菜单只能人工看。Hanoi 的两处问题是 Claude 目视得出，尚未由用户复核。
- 一行多价（"Bacon 3.9 / Smoked Salmon 3.9"）与老式 HTML 的名称片段需要规则补充或人工修正。
- 官网发现仍靠人工检索：17 家候选查 33 次，是最大的人工耗时项。
- 分析结果存于开发库，非正式环境。

## 八 建议

1. B 阶段前先做视觉路径评测（真实模型或人工转录流程），因为可见缺陷集中在图片菜单。
2. 在工作台加入“候选文件”面板，让操作者一键接入 `menu_not_in_html` 里的 PDF/图片链接（当前需手动填 URL）。
3. 对 Squarespace/Wix 站考虑 Playwright 渲染或平台菜单接口，作为可选步骤而非默认。
4. 下一批 50 家由真人执行并计时，才能得到人工基线；本报告的分钟数只能用来估工具处理量。
