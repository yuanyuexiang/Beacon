# D47 Gmail 实施步骤（2026-10-12）

用户授权按以下顺序实施，未授权向真实客户发送测试邮件。

1. 独立 Gmail 服务：HTTP 管理接口和 Streamable HTTP MCP 共用邮件核心；内部 Bearer 认证，凭证/审计持久化，OAuth 回调、导入、连接检查和断开。
2. 单家发送：复用已审批内容和渠道准入；展示最终邮箱、主题与正文，操作者确认后提交；以任务绑定唯一发送记录，记录 Gmail message/thread ID，未知结果不重发。
3. 回复同步：只沿已知发送线程读取邮件头，去除自己发送的消息，幂等回填事件并暂停后续任务；拒收/退订分类不凭邮件头猜测。
4. 批量队列：选择既有邮件任务，逐封预览，确认整批最终内容后入持久队列；执行前复核内容/准入/抑制，账户发送开关和队列开关默认关闭；限额可配置，0 表示没有本地限额；过期预览重新确认。
5. 验证：普通测试不依赖真实 Gmail；本地已有凭证允许导入独立存储做只读兼容检查，Google 重新授权由用户在浏览器完成，不自动联系客户。

部署：gmail-service 不暴露公共端口，Beacon API 代理 OAuth 回调与管理；服务与 API 的访问密钥通过 Compose secrets。刷新令牌与 SQLite 发送尝试审计存专用卷；Beacon PostgreSQL 保留业务状态。单实例 worker 持久领取队列，重启中途的发送先查询服务结果，不盲目重发。服务器 OAuth 使用 web 客户端与固定回调 URL，已有 installed 客户端可导入离线令牌但不能冒充 web 回调客户端。


## 验证结果

四步功能及容器部署已实现。普通测试覆盖预览、版本绑定、暂停、单次发送、未知结果恢复、批量确认原子性和回复幂等；真实客户发送未执行。旧 OPC 凭证格式及权限兼容，Google 刷新返回 invalid_grant。用户选择本机重新授权；Google 页面出现“出了点问题”及 401，本次等待超时，未取得新令牌。需重新授权成功后再导入并验证真实连接；服务发送和队列保持暂停。
