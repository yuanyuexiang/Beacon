## 实施与验收

详情联系方式统一“准备触达”，WhatsApp／FB／INS／LinkedIn／TikTok／YouTube／X 默认手机执行。单台在线就绪手机自动选择，多台时明确选择；缺少手机时可刷新或前往配对。电话继续通过显式“通过 WhatsApp 联系”核对国际号码，保留原记录。邮件沿用 Gmail；表单、电话拨打、邮寄保留人工路径。

共用 MessageComposer 展示收件人、正文、手机和联系动作；最终预览包含手机、本方当前登录账号、目标链接、动作与正文，确认即事务内创建任务和 Execution 队列，不再打开第二层预览。既有任务仍可在沟通页查看及处理；同渠道草稿切换联系人复用未转换草稿，已发送联系人不阻止其他联系人。

`POST /communication/drafts/{id}/preview` 可选提交 device_id／action，confirm 同时绑定手机快照。手机改变、失联或内容改变后拒绝旧预览；重复确认返回已有任务。旧版无手机参数的准备流程保留兼容，手机工作者实际执行检查不变。无需新迁移。

验证：`tests/test_mobile_journey.py` 参数化六类社媒和同渠道联系人切换、设备状态变化；`scripts/verify_mobile_outreach_journey_ui.py` 模拟详情选 FB → AI 起草 → 一次预览 → 入队。脚本默认 localhost:3000，可用 BEACON_UI_URL 指定测试服务。所有 API 截获，不触达真实账号。

真实 WhatsApp／FB 既有测试结果不扩大到其他平台。回复继续使用通知收件箱与首次会话关联，真实通知验收尚待用户安排。

验收结果：后端全量 pytest 通过；前端 36 项单测、类型检查、构建通过，ESLint 仅保留详情页原有两处 img 提示。手机闭环和 Gmail 简化发送模拟 UI 通过，Ruff／mypy／部署声明校验通过。本地 API／Web 镜像已重建并启动，双端健康检查通过；未提交、推送或发布云端，未新增真实消息。
