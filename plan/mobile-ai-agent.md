# 手机 AI 执行开发地图

2026-11-11 用户批准。复用现有配对、冻结任务、执行日志、截图、通知回填；自主实现，不复制 AGPL 项目代码。dsh-Go 仅作架构研究参考。

## 目标

以统一模型驱动“观察→单步决策→执行→再观察”，替代各平台规则优先的发送主线。后端调用现有 mobile 用途模型，手机不保存模型密钥。模型只选择动作，消息正文固定来自网页确认快照。发送后进入只读核对，不重放发送。

## 实施顺序与验收记录

- [x] P1 梳理基线：当前 navigation 是四次 AI 兜底，只找入口；WhatsApp 独立规则流程。保留兼容旧 APK，新增 v3 AI 执行协议。
- [x] P2 统一观察／动作：控件树、截图、单步节点点击／输入／发送／滚动／返回，观察标识校验、敏感页暂停。
- [x] P3 后端 Agent：mobile 模型、任务绑定、阶段与调用记录、停止／过期检查、发送后只读、结构化结果。
- [x] P4 手机接入：全平台共用执行循环，网页实时步骤／截图；无入口与跨渠道入口返回明确结果。

## 结果语义

sent=观察到本次新增发出消息（不是已读）；unavailable=已处理但不能联系；needs_action=需要用户操作；unknown=已尝试发送但不能确认；failed=执行故障。处理完成与发送成功分开。

## 本轮实现与验证（2026-11-11）

- 新 APK 通过 protocol=3 心跳启用 `ai-agent-v1`；旧 APK 保留兼容执行路径。无数据库迁移。
- `/api/mobile/device/jobs/{id}/agent` 一次只返回一个动作。每步绑定任务、租约与页面标识；模型调用期间取消或改动任务时，返回的旧动作会被丢弃。
- 手机统一执行全部已登记平台，提供控件树及可用截图；填写采用网页冻结正文，发送前检查内容，发送尝试后只观察结果。最多 24 步结束本轮，防止无进展循环；不是每日查询额度。
- 网页执行抽屉展示模型、逐步操作、结果截图和其他渠道入口。发现 Facebook 的 WhatsApp 按钮会记录为其他入口；AI 只采用页面中实际可见的联系值；网页“转用此渠道”可补填或确认号码／邮箱／主页，去重保存并直接进入该联系人消息准备，仍需重新预览发送。隐藏号码不凭空推断。
- 六个平台新增明确选择“作品公开留言”，预览再次显示公开提示。私信失败不会自动变成公开评论。评论回复的自动收集仍依赖系统实际通知及关联，不保证完整。
- 后端手机／渠道／发送／通知专项 85 项通过，新增协议及替代入口两项补测通过（Agent 共 13 项）；Ruff、mypy 184 文件通过。Web 43 项、类型、lint 和生产构建通过（详情页原有两处 img 建议警告）。Android JVM 单测与 release APK 构建通过；Mobile 类型检查通过。
- APK：`apps/mobile-agent/android/app/build/outputs/apk/release/app-release.apk`。本轮未安装、未真实发送、未提交或部署。

## 使用与后续验收

1. 设置 → AI 模型，为“手机页面理解／执行”对应 mobile 用途选择可用模型，推荐支持图片输入的模型并通过能力测试。未配置时返回可读错误，不静默使用其他供应商。
2. 安装新 APK、保持原配对，连接平台并开启无障碍与自动执行。网页检查手机在线及安装平台。
3. 门店选择联系方式 → 手机触达 → 选择私信或明确的公开留言 → 编辑并预览完整正文 → 确认交给手机。
4. 在客户沟通的手机执行结果中查看步骤、结果和截图。“不可联系”代表本轮已处理；“结果不确定”需查看实际页面，不能据此重复自动发送。
5. P7 按平台做真实发送及回复验收后，再执行 P8 删除不再需要的旧发送逻辑。当前旧路径是旧 APK 的兼容入口，不能未经验收直接删除。
