## 实施约束

先复用 PostgreSQL 检查点与 advisory lock，不增加 Redis/Celery 运维依赖。API 生命周期托管后台执行线程，持久化任务是恢复依据；每轮执行使用独立数据库会话。跨进程依靠数据库锁互斥。历史未完成任务不因升级自动产生外部调用，用户继续后才进入后台队列。

AI 只能根据取得的证据给出建议；业务准入、内容审批、抑制与发送前复查继续生效。Gmail 当前仅有邮件头授权，正文理解先提供显式粘贴入口，不把邮件头当正文；自动正文同步需要新增权限后独立验收。

## 已落地的第一版与验收入口

1. 新任务创建后由 `/workflow/{id}/resume` 加入后台；API 托管线程每轮取检查点、取得名单锁后处理，失败停止并等待重试。旧任务不自动加入。无新服务、无数据库迁移。`BEACON_WORKFLOW_WORKER_ENABLED=false` 仅用于隔离测试／停止调度；常规部署默认开启。
2. 官网 HTML 复用 1 小时，按 URL 索引、SHA-256 校验，最多 500 份，过期条目后续访问清理；每次仍校验公网地址，网络失败不回退成旧缓存成功。带查询参数和测试 transport 不缓存。研究判断与消息起草记录用途、模型、版本、时长、token 使用及错误类型，最多 500 次，设置→技术文档可查看最近 100 次；不存提示词或密钥，不用未知单价编造成本。
3. 详情→销售助手可生成带引用摘要，资料变化标记过期。当前依据登记资料、服务资料与最新已核对菜单；不以模型推断替代联系方式准入。菜单增加空提取、缺来源、重复条目检查，自动模式下有文本但无条目时可转真实 DeepSeek；菜单索引页不误作转录，仍须事实核对。
4. 详情→销售助手→理解客户回复，显式粘贴正文并选择渠道；先记录收到回复、暂停待发任务。AI 拒绝／退订结果进入抑制；一般意向须点击确认后才计入已有漏斗统计。跟进建议可保存为待确认文案（含发送身份／退出说明），使用原有审批与任务流程。名单“下一步”列可按工作优先级排序：客户回复、待执行、待完善，停止触达最后；不是购买概率。

## 评估与边界

- 固定合成回复集：`apps/api/tests/fixtures/ai-evaluation/replies.json`。真实模型评估命令：`cd apps/api && uv run python ../../scripts/evaluate_reply_ai.py`。报告在数据目录 `evaluations/`，不提交客户原文或真实凭据。
- 离线回归只证明流程／约束正确，不证明真实模型分类准确。合成评估也不代表客户成交率。
- Gmail 自动正文同步及新增 scope 本轮没有开启；现有邮件头同步继续工作，不能用邮件头生成回复理解。粘贴正文仅用于本次模型请求，持久化摘要、短引用和正文指纹。
- 后台名单执行属于 API 生命周期，API 停机期间不执行，重启后恢复。单个外部请求不能立即中断，取消后其已取得的结果可能仍保存，但不得恢复任务执行状态。
- 共享缓存位于既有数据卷；关闭页面／重新部署不会清除结果。没有新增生产 compose 服务或绕过部署 hash 检查。
