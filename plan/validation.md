# Beacon 小样本验证流程

版本：v0.3，2026-09-30。已确认英国试点且没有现成名单；目前仅完成流程设计，尚未生成样本，以下步骤尚未执行。关联：[路线图](roadmap.md)、[任务](tasks.md)。

## 一 验证的问题

1. 目标餐厅中，多少能获取菜单并确认值得提出的问题？
2. 其中多少具备本次允许使用的联系渠道？
3. 每条线索需多少人工研究、纠错、审核和销售时间？
4. 实际联系后，是否有人愿意看示例、讨论需求或询价？

小样本用于发现瓶颈。既不承诺成交，也不把零成交直接解释为项目无效。

## 二 分开技术研究与外部触达的启动条件

T0/T1 仅需研究地区和来源、研究执行人、数据处理条件、受控存储及研究工时/费用上限。经营毛利、销售身份、联系人授权和商业门槛属于 B 的条件，不阻断菜单技术探索或 D 的最小工具开发。

T1 约 10 家用于找出可行路径；D 开发可在 T1 通过后开始。V 约 50 家新候选用于扩大验证，B 人工联系可在自身条件齐备后与 D/V 并行。具体依赖见 [路线图](roadmap.md)。

### 输入与职责

| 输入 | 当前状态 | 用途 |
|---|---|---|
| 国家与已有名单 | 英国已确认；现有名单为空 | 从公开名录建立候选池 |
| 来源、城市和类型 | 建议 FSA 底表；伦敦和堂食餐厅为取样建议，待落实 | 先取一个区域，不代表整个英国 |
| 样本规模 | T1 约 10 家；V 约 50 家新候选 | 分开探索集与扩大验证集 |
| 研究执行人与存储/研究预算 | T0 落实 | 技术探索启动条件 |
| 审核、销售负责人 | B 前落实，可兼任 | 不阻断技术研究；明确发送和回填责任 |
| 订单贡献毛利、复购证据 | 待客户提供 | 不能套用旧报告的 330 欧元毛利 |
| 工时成本、销售容量、现金预算上限 | 待定 | 计算投入与可承担获客成本 |
| 联系身份、渠道规则、账号条件 | 待确认 | 逐条准入，未确认不联系 |
| 观测窗口、回复/意向目标、成本上限 | 待经营方冻结 | B 前写下，不能看完结果再改门槛 |

### 英国候选名单的来源方案

已知条件：无现成餐厅名单，英国试点。技术来源由实施方选择，不要求经营方理解数据 API。

1. **候选底表：FSA 食品卫生评级公开名录。** 用门店名、地址、邮编和 FSA 标识建立候选池；其经营类别不等于精准菜系，也不等于已核实的法律主体。官方提供下载与免费 API：[开放数据](https://ratings.food.gov.uk/open-data?lang=en-US)、[API 文档](https://api.ratings.food.gov.uk/help)。
2. **菜单与联系方式：餐厅官网。** 先按名称、地址人工核对官网，保留无法找到的记录；不以卫生评级推断菜单设计需求。
3. **可选补全：Overture Places。** 网站匹配成为瓶颈后再引入，核对名称、地址和位置；不是首批必须搭建的数据管道。[官方指南](https://docs.overturemaps.org/guides/places/)包含网站字段及数据来源说明。
4. **主体核验：在准备联系时单独进行。** 门店存在、官网公开、公司名称相似都不能直接推导出允许营销；不把 FSA 名录称为可直接发送的客户名单。

建议 T1 在伦敦一个明确行政区取约 10 家技术探索候选，V 再抽取约 50 家新候选，人工核对堂食餐厅属性；连锁、非目标类型及未知均保留分类原因，不悄悄替换样本。地区和类型属于实施建议，尚未确认或抽样；后续按冻结规则建立正式批次。

## 三 抽样与证据

确定一个地区和一至两类餐厅，固定数据版本、抽样日期、筛选表达式和随机种子；人工名单记录导出日期及选择方式。禁止仅选“有官网、有菜单”的餐厅后宣称总体覆盖率。

去重后冻结批次 `batch_id` 与候选数 N。无网站、获取失败、无法匹配、主体未知都保留并编码原因。T1 探索样本全部可调试，不当独立验收。V 新批次至少留 20% 冻结验收，不混入 T1 样本；报告各菜单格式实际数量和覆盖限制，不能把特定地区样本外推全国。技术夹具可另行补齐格式，但不混入覆盖率分母。

受控存储保存原始响应/文件、URL、采集时间、数据版本、脚本版本、文件 hash、人工记录。只保留许可允许的材料；仓库仅保存脚本、字段说明及脱敏夹具。旧笔记中的“实测”在脚本和产物复现前仅作参考。

## 四 逐家操作

1. T1 先核对门店与官网，主体未知可继续内部菜单分析；到 B 准备联系前再核对经营主体和逐条准入。不凭名称或邮箱域名断言。
2. 记录网站和菜单获取结果、格式和失败原因；发现错误官网立即停止沿该路径补全。
3. 提取菜单，检测低清、阅读困难、溢出或格式不一致；每项附位置证据，由人确认。无问题也是有效结果。
4. 用一个模板生成局部示例；逐项核对菜名、价格，不新增成分或过敏原事实。
5. 技术阶段可将渠道准入记为未知，不要求先成为可联系线索；B 前分别核对联系方式是否有效、该次联系是否允许。未通过准入仍计入候选分母。
6. 为允许联系的线索准备短文案、身份与退出方式；人工审批绑定内容版本。编辑后重新审核。
7. B 条件齐备后由销售逐条执行，每次发送前复核拒收及回复；点击链接只记打开，不记发送。
8. 回填实际发送、对方回复、录入时间和结果。人工回复先暂停；拒绝/退订立即抑制；是否继续由负责人明确决定。

## 五 渠道准入基线

这是首期产品控制规则，具体适用条件需由经营方在目标市场确认。准入状态为 `unknown/allowed/blocked`，附规则版本、证据、审核人和复核时间；只有 `allowed` 能进入执行任务。

| 渠道 | 首期处理 |
|---|---|
| 邮件 | 核对订户类型、使用依据、身份/退出方式、拒收名单及服务商条款；主体未知或个体无适用授权/例外证据时不放行 |
| WhatsApp | 不默认冷触达；记录收件人的 opt-in 证据、适用身份和范围；公开号码或 wa.me 链接不替代授权 |
| Instagram | 暂不纳入主动联系；发现账号仅作资料，不生成发送任务 |
| 电话 | 英国候选需核对 TPS、CTPS、自有拒收记录及适用同意；不能把“个体户”自动映射为可拨打 |
| 联系表单 | 暂不作为电子营销规则的替代渠道；条件未确认则不执行 |
| 实物样品 | 暂缓印刷邮寄；仅生成内部审核素材 |

核查依据（2026-09-30）：[ICO B2B 指引](https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/business-to-business-marketing/)区分订户类型并要求电话名单筛查；[WhatsApp Business 政策](https://whatsappbusiness.com/policy/)列出 opt-in 要求。规则更新时重审准入，不把上述简表视为所有国家的通用结论。

Google 数据暂不接入首版。[Places 官方政策](https://developers.google.com/maps/documentation/places/web-service/policies)限制预取、缓存和存储；不能因 Redis 有 TTL 就放行。未来按适用条款逐字段确认，并覆盖原始响应、日志、缓存与备份。

## 六 记录字段与口径

可先用 CSV 表，不要求立即建数据库；所有时间使用带时区的 ISO 8601，缺失值留空并附原因，不以 0 替代未知。

| 记录表 | 最小字段 |
|---|---|
| 批次 | batch_id、国家/地区、类型、来源版本、抽样方法/种子、N、冻结时间、观测截止日、目标版本 |
| 线索 | lead_id、batch_id、门店、官网、主体状态/证据、菜单 URL/格式/hash、获取结果、人工确认问题/证据位置、纠错耗时 |
| 联系渠道 | lead_id、channel、contact_ref、可用状态、eligibility、规则版本、授权/筛查证据、审核人/时间、复核时间 |
| 审核内容 | lead_id、content_id/hash、模板/模型版本、证据引用、审批状态、审批人/时间 |
| 活动 | event_id、lead_id、channel、content_id、动作、实际发生时间、录入时间、操作者、发送结果、回复分类、抑制动作 |
| 成本 | batch_id、lead_id（可空）、成本类别（setup/processing/outreach）、操作步骤、实验组、币种、金额、汇率及日期、人工分钟、计价依据 |

统计以去重餐厅为主：N=冻结候选；M=取得菜单；I=人工确认至少一个问题；E=同时符合目标类型、有确认问题且至少一个允许渠道；S=至少实际发送一次的餐厅；R=人工回复餐厅；P=明确愿意看示例、讨论需求或询价的餐厅；Q=明确请求报价的餐厅。

报告 `M/N`、`I/M`、`E/N`、`R/S`、`P/S`、`Q/S`，同时写分子分母。分母为零写“不适用”；自动回复不计 R/P。多渠道汇总去重，分渠道结果单列，不能相加冒充客户数。发送成功不等于送达，未知送达状态保留未知。后续撤回兴趣保留事件，并单列当前有效意向。

### 成本与人工对照

成本逐条标记，不能把总验证成本当作稳定运行的单位成本：

| 类别 | 包含 | 报告方式 |
|---|---|---|
| setup 一次性准备 | 来源研究、脚本/工具开发、初始模板、培训 | 单列总投入；如摊销，明确假设批量，不混入持续成本 |
| processing 持续处理 | 每家查找、获取、失败处理、纠错、审核、素材准备 | 总人工分钟/N、总处理成本/N；另列已确认问题线索 I 的摊销成本；无准入时不等待 E |
| outreach 销售操作 | 准入核对、人工联系、回复回填及后续销售沟通 | 单列总额、每 S 的成本；结合 processing 报告每 P 的持续成本 |

总现金支出和含人工估值的总投入都保留；人工估值=分钟/60×工时单价，单价缺失先只报分钟，不假装免费。总投入/P 与持续成本/P 分列，零分母写不适用。每 E 的摊销时间明确为相关总处理/准入工时除以 E，不称为单条实测中位数；单条耗时分布另报。

工具是给客户员工用的，验证对象是真人使用工具的每家处理分钟数、卡点和返工量，不是工具与纯人工的因果比较。V 第二批由真人用工具处理全部候选并逐步计时；重试、等待和人工纠错均计时；记录操作者和经验，同一份菜单不重复处理。纯人工对照降为可选：客户需要对外的“节省工时”数字时，再抽约 10 家由真人不用工具处理，同一质量标准，只报观察差异，不声称因果效果。

按菜单格式报告耗时中位数、失败率、纠错量与确认问题的准确情况。报告观测截止日和各家首次触达后的天数，未满 B 观测窗口的无回复不记成熟结果。

## 七 分阶段判定

**技术门槛：**T1 在研究时间盒内至少一份真实菜单完成提取、证据、人工确认和局部样稿，其他候选失败可解释；确定支持格式及开发范围后进入 D，不要求正向回复。无路径则先修正技术方案。D 按 development.md 验收，V 测质量与持续处理成本，不以成交率决定工具是否交付。

**商业及规模化门槛：**以下条件用于 B 和后续规模化投入，不能反向阻断 T1/D。

B 前在批次记录中冻结：现金预算上限 B_max、每 E 持续处理及准入摊销分钟上限 T、最低可联系数 E_min、完整观测窗口 W、最低正向意向数 P_min、每 P 可接受持续成本 C（processing + outreach，不含 setup）。具体值来自客户毛利和销售容量，当前不编造行业基准。

- **继续**：安全与证据要求通过，E ≥ E_min，人工耗时和预算不超限；完整观测窗口内 P ≥ P_min 且每 P 持续成本 ≤ C，经营方认可下一阶段投入。
- **调整再测**：有可解释瓶颈但证据不足，例如主体识别困难、菜单缺失或人工纠错成本高；缩小目标类型或改流程，另建批次，保留原结果。
- **暂停/停止**：出现拒收后继续联系、无许可的数据处理、不能满足渠道条件或预算耗尽时先暂停相关流程；修复并复核后才恢复。充分观测后仍未达预设门槛，由经营方决定是否终止。
- **未验证**：无名单、无实际触达或窗口未结束时，不给出商业通过结论。当前处于此状态。

经济性用实际贡献毛利计算：单笔贡献毛利=订单收入−设计交付−印刷/物流−其他随订单变化成本。盈亏平衡客户数=同期固定投入/每客户预期贡献，复购仅在有证据时计入。经营预算另列销售和样品支出，避免与贡献毛利重复扣除；缺输入不输出回本月份。

## 八 报告交付格式

后续每批报告包括：批次与样本限制、各步骤分子/分母、证据复现位置、问题确认与纠错率、工时及成本、渠道准入/拒收事件、回复与有效意向、观测窗口、预设门槛对照、继续/调整/停止及理由。

最终给出“最值得自动化的三个耗时步骤”和“仍应人工判断的事项”，据此确定 M 后续投入范围；D 的修正仅限已承诺首版边界。当前没有样本结果，不预填成功数据。
