# 社媒渠道服务操作说明

应用创建、凭据获取及逐项配置见[社媒 API 应用与授权配置指南](社媒API应用与授权配置指南.md)。

## 当前能力

D48 首期接入 Facebook Page 与 Instagram 专业账号的普通文字回复。设置页管理账号、应用和凭据；任务页的“社媒会话与发送”提供会话关联、最终预览、确认、发送记录及对账。凭据可稍后补齐，未连接时不执行真实发送。TikTok 及 LinkedIn 自动消息 provider 尚未接入；LinkedIn 已有独立渠道与原有人工任务流程。

Gmail 继续使用独立邮件服务和现有页面。两类渠道复用销售任务、内容审批、准入、抑制、回复暂停和审计；社媒的会话身份与授权版本另行保存，Gmail 无需改成社媒账号。

## 启动服务

首次启动前准备内部密钥：

```bash
python3 scripts/configure_gmail_service.py
python3 scripts/configure_meta_service.py
docker compose -f infra/docker-compose.yml up -d --build
```

`meta-service` 是内部 HTTP 服务，端口 8091 不映射到宿主机。`outreach-worker` 每 5 秒处理未处理的入站事件与已确认任务。内部 Bearer secret 与平台 Token 分开。两者各运行一个进程；发送请求账本持久化，进程重启不会自动重发结果未知的 POST。

代理按部署环境配置 `infra/.env` 的 `BEACON_META_PROXY`，例如本机 Clash 可用 `http://host.docker.internal:7890`。服务器填写实际网络出口，留空直连。应用 ID、Secret、Access Token 在设置页保存到服务数据卷，不放 Compose 环境变量或源码。

## 配置应用与账号

1. 设置 → Facebook / Instagram 渠道 → 配置 Meta 应用。填写 App ID、App Secret、自设至少 16 字符的 Webhook Verify Token、Graph API 版本和 OAuth 回调。默认版本为 `v25.0`，实际使用时核对应用支持版本。
2. 本机回调是 `http://localhost:3000/api/outreach/oauth/callback`；服务器使用实际 HTTPS 域名，并在 Meta 应用中登记相同回调。
3. 添加本方发送账号，填写平台、认证路线、名称及发送身份 ID。FB 填 Page ID；INS 填专业账号 ID。该步骤不要求 Token，不会发送消息。
4. Facebook Login 可以点击“浏览器授权”。INS 使用该路线时还需填写关联 Facebook Page ID。回调状态有 10 分钟有效期且只能用一次；取消或错误后重新发起。
5. 也可以导入已有 Token：FB 使用 Page Access Token；INS Facebook Login 使用关联 Page Token；INS Instagram Login 使用该专业账号 Token。首期未实现 Instagram Login 的浏览器授权和长期 Token 自动刷新。
6. 点击“检查连接”，核对 Token 所属发送身份。身份检查成功不证明应用已取得外部用户所需访问级别；消息权限仍需要真实测试账号联调。
7. 完成应用权限、Webhook 及测试后再设置“允许发送”。队列开关另设，默认关闭；每个账号默认滚动 24 小时最多尝试 20 次，可以调整。

导入新 Token、重新授权、断开、身份检查失败或应用关键配置改变，会暂停发送并使旧授权预览失效。账号身份在创建后固定；更换 Page 或专业账号应新建账号，不能沿用旧会话的收件人 ID。

Facebook 浏览器授权申请 `pages_show_list`、`pages_messaging`、`pages_manage_metadata`；INS Facebook Login 申请 `pages_show_list`、`pages_manage_metadata`、`instagram_basic`、`instagram_manage_messages`。应用产品、外部用户权限审批、账号角色与实际 scopes 需按选定路线核对，不能混用 Instagram Login 的 `instagram_business_*` 权限。

## 配置 Webhook

在 Meta 控制台配置回调 `https://部署域名/api/outreach/webhook`，Verify Token 与设置页一致，订阅所选产品的消息事件及对应 Page／专业账号。首期不自动代替控制台完成应用订阅或权限审批。

GET 验证回传 challenge；POST 使用 App Secret 验证原始请求的 `X-Hub-Signature-256`。不公开 App Secret 或内部服务端口。API 只接受不超过 1 MB 的请求，忽略本方 echo 和非消息事件。

合法入站消息按平台、发送账号和消息 ID 去重，保存会话与事件。只接受对应接收身份的消息；未配置的发送账号被忽略。未知联系人不会按名字自动匹配餐厅。重复事件不重复暂停，乱序旧消息不延长窗口。

服务不可用返回非成功状态以便平台重试；已持久化事件也由 worker 继续处理。API 与 worker 需长期在线，平台重试和可用性仍受其实际策略影响。

## 单家回复与队列

1. 让明确允许的测试对象向本方 Page／专业账号发消息。任务页出现会话后核对对方身份，关联正确门店及该平台的准入记录。
2. 关联不自动批准准入。已收到的回复会暂停该门店的待执行任务；负责人确认后恢复或创建相应任务。
3. 使用已有已审批短文案。首期只支持 1 至 1000 字符，不发送附件、不做评论私信回复、窗口外模板或广告。
4. 从会话表明确选择“预览回复”。只有一个账号匹配时也可勾选任务批量预览；多个账号匹配时要求明确选择，避免系统代选身份。
5. 核对发送账号、收件人 ID 和最终正文，勾选确认。单条进入等待发送，整批进入队列；整批审批的任一记录无效时整批不入队。
6. 执行前再次检查准入、内容审批、抑制、任务状态、授权版本、会话关联、窗口及发送开关。排队不保证执行时仍允许。

首期采用最近入站消息后 24 小时以内的保守普通回复范围，两平台均不启用窗口外例外。预览最多有效 30 分钟，并受会话窗口截止时间约束；队列等待期间过期需重新预览。最终窗口与接口支持仍需实际账号验证。

返回平台消息 ID 表示平台接受，不声明已送达或已读。真实发送回填 `sent_social`，计入漏斗及导出；人工发送仍使用 `sent_manual`。回复进入已有销售事件并暂停后续任务；明确拒收通过现有拒收回填流程进入抑制，首期不使用 AI 自动判断拒收。

## 未知结果与对账

服务在外部 POST 前写入持久化账本，同一请求键重复提交只返回已有结果。网络超时、平台服务错误或进程中断保持未知，不自动再次 POST。明确的提交前拒绝会阻断执行；平台明确拒绝的发送失败可重新预览。

“查询结果”读取服务账本，不按相似文案猜测平台消息。若账本仍未知，先在平台实际核对，再使用“人工核对结果”：已发送需真实消息 ID、实际发送时间和核对证据；确认未提交需明确证据。无法确认则保持未知。人工结果会写入审计和服务账本，已有明确结果不可覆盖。

若服务完全没有请求记录，人工对账入口不会直接放行重发，应先核对 API／服务执行日志和平台实际记录。数据卷丢失不能当作未发送证据。

## 存储与维护

- PostgreSQL：账号元数据、准入与会话关联、审批、队列、发送结果及入站事件；没有平台 Token。
- `beacon-meta-data` 卷：权限为 0600 的应用与账号凭据、审批签名密钥、SQLite 请求账本及 OAuth 状态。容器运行用户 UID 10002。
- 最近入站消息只保存最多 2000 字符用于关联与回复处理；worker 在最后入站超过 30 天后清除该内容。事件只保留消息 ID 与时间等必要元数据；发送文案继续依现有业务保留规则处理。
- 普通日志不回显凭据或授权码。配置校验错误不返回原始请求输入；账号接口不返回 Token 或审批凭证。

数据库和文件备份使用现有工具。Meta 卷另行备份时先停止服务及 worker，确保账本一致：

```bash
docker compose -f infra/docker-compose.yml stop meta-service outreach-worker
docker cp beacon-meta:/data ./受控备份目录/meta-data
docker compose -f infra/docker-compose.yml start meta-service outreach-worker
```

恢复时同样停机，并将备份放回 `/data`，确保文件 UID／GID 为 10002 且凭据权限为 0600。必须配套恢复账号数据库、服务账本及审批密钥；不完整恢复时保持发送暂停并先核对平台记录。备份目录不得提交 Git。

### 2026-10-24 无凭据阶段修复

浏览器重连失败或取消保留原连接；新身份验证通过才替换并暂停发送与队列。回调必须来自发起授权的管理员会话及浏览器；重新登录、断开或修改账号后应重新发起授权。页面“身份已核验”只表示 Token 身份匹配，消息权限、Webhook 订阅和真实收发仍需账号联调。API 与 Meta 服务需一起更新；更新前发起的旧授权需重新发起。
