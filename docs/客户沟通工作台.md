# 客户沟通工作台（D60）

详情页销售准备采用双栏：左侧联系人卡片，右侧文案与任务；窄屏自动上下排列。负责人旁“管理”可分配或查看记录，“核验与设置”展开联系方式依据与准入操作。已有草稿的“发件身份与退出说明”可展开修改，核对文案后在底部创建任务。

本地验收版本。名单负责找店、完善证据与准备触达，沟通工作台负责执行任务和后续沟通；同一门店在不同名单共享沟通历史。本次开发不执行真实客户触达，不发布服务器。

## 客户工作流程

页面以“完善客户资料 → 准备触达 → 确认发送 → 沟通跟进”标明当前工作区域，不把导航位置当成客户资料已齐全的证明。线索详情与名单共用沟通状态和下一步；详情分为“销售准备、菜单资料、来源与历史”，单家直接在页内准备，批量继续使用共用准备抽屉。

菜单分析自动选择处理方式：可读 PDF／HTML 直接提取，图片／扫描 PDF 使用已配置的真实 AI。事实核对与内容审批分别进行，核对菜单不等于授权发送。样稿是可选资料，不是创建触达任务的条件；短文案生成与版本审批集中在销售准备区，批量操作在准备抽屉。旧文案与样稿保存在折叠的历史区。

没有菜单也可以先完善联系方式、保存准备草稿；未经核对的问题不能生成对外主张。创建任务仍复核准入、已审批文案、抑制和来源有效性。分析详情和版本可展开查阅。

## 单家详情

- **销售准备**：直接读取已有草稿，不因打开页面创建草稿或发送消息；联系人可手动添加或从官网查找。点击某项“用于本次触达”会保存该项选择。推荐、渠道准入和可达性分开显示，原因及原文来源可展开。
- **文案与任务**：选择渠道和联系人、准备并审批文案，再创建任务。已存在任务时优先显示任务与回复入口。菜单不可得时可生成询问菜单／负责人文案，不要求先有菜单。
- **菜单资料**：官网候选、菜单链接和上传文件统一获取后分析；选择当前文件，左右对照原文件与分析结果。问题可标为属实／不属实／待核对。文案生成时明确选择已核对的菜单分析；历史版本保留。
- **来源与历史**：维护官网和筛选判断，查看官网核验及历史网址。自动研究和 Google 实时价格／照片等工具折叠在“补充来源与查询工具”。
- **官网变更保护**：未编辑时自动同步新官网；存在未保存输入时先选择采用最新官网或保留输入。提交时仍校验当前官网，发生并发变化则拒绝覆盖。
- **重新分析**：默认查看已存结果；点击“重新分析”确认后生成新版本，新版本需重新核对，相关文案审批重新评估。
- 部分资料加载失败时，其他成功区域仍可使用；点击“重试加载”补读。只读用户可以查看文件、来源与任务，不能修改或准备触达。

## 从名单继续

1. 在“批次与线索”选择名单并筛选门店，勾选客户后点“准备触达”。未勾选时使用当前筛选结果，不限当前表格页。
2. 选择邮箱、TikTok、LinkedIn、Facebook 或 Instagram，指定执行方式与负责人，点“检查并保存草稿”。缺联系方式、准入或已审批文案时逐家显示缺项，草稿保留。
3. 展开客户行补联系方式、填写真实准入依据、选择文案；有已审核菜单事实时可生成待审批文案。编辑后保存新版本，再明确审批。
4. “创建就绪任务”只转换满足条件的草稿，不发送。其余草稿保留；重复操作复用同渠道未完成任务，首次触达也复用已发送任务。
5. 点击“进入本次触达工作台”，带入名单、本次新建任务组、客户及具体任务。逐家入口能定位已有任务。返回来源页面保留名单、搜索、类型、预筛状态、页码及每页数量，勾选保留在浏览器会话。

未完成的准备草稿留在名单侧，沟通页只展示已有任务（包括待发送、已暂停、已结束）或沟通记录的客户；不必等到发送成功。沟通页没有首次触达准备入口，空状态引导回名单，历史链接也不能把原始线索带入执行区。渠道、负责人、搜索、名单与分页在这个范围内筛选；只有草稿的客户不会因筛选而混入。

线索详情同样提供准备与查看入口；名单沟通进展回显未准备、准备中、待执行、等待回复、已回复、已暂停、已抑制。

## 执行与回填

- 人工执行取得已审批文案和平台入口。打开、复制不会记为发送；实际在平台发送后，由操作者明确确认并回填真实时间。
- Gmail 接口复用原有账号状态、完整预览、明确确认与未知结果对账；未授权或开关关闭不能绕过原检查。
- FB／INS 接口仅用于已授权账号、已关联准入且在回复窗口内的会话；主页地址不能直接接口发送。TikTok／LinkedIn 当前提供人工执行。
- 客户会话展示人工记录、Gmail 回复邮件头和平台已同步内容，不声称已取得 Gmail 正文。可回填回复、意向、下一步、拒收、退订、退信。
- 回复暂停未完成任务，由人复核恢复；拒收／退订抑制并取消待办；退信使联系值失效。创建、打开、回填时重新检查准入、审批、抑制。
- 已有接口排队、提交或未知记录时先核对原结果，避免人工重复发送。跟进时间只作安排，不会定时发送。
- 首次触达已发送后，在会话中明确选择“人工准备下一次跟进”才能新建跟进；未完成任务仍优先复用。

## AI 触达消息（D72）

1. 管理员在“设置与说明 → 我们的服务 · AI 触达资料”填写真实公司、菜单设计与印刷服务；案例及限制可选，不自动虚构。
2. 门店详情选用联系人并保存草稿，展开“发件身份与退出说明”填写真实身份；选择已核对菜单，或留空询问菜单／负责人。
3. 点击“AI 起草触达消息”。邮件含主题、正文，社媒为简短消息；“为什么这样写”可查看依据和待补信息。无明确问题的菜单也可生成合作介绍。
4. 修改主题／正文后保存修改，核对事实、身份及退出说明，再“确认消息内容”。创建任务仍不发送，实际发送必须完整预览确认。
5. 邮件预览主题留空使用消息内已确认主题；更改需返回消息修改确认。旧模板消息没有主题时仍需填写。

AI 复用已记录资料，不在起草过程中重新抓取网站／调用 Places。没有真实模型或服务资料时明确提示，原消息保留。服务资料或门店资料变化、菜单变更及新消息版本会触发重新确认。

## 英国客户的服务资料与署名（2026-10-25）

入口：**设置 → 我们的服务**。内部事实可以用中文维护；新起草的客户消息使用英式英语（en-GB），AI 起草依据使用中文。

| 内容 | 怎么填写 |
| --- | --- |
| 公司／品牌介绍 | 真实公司名称与业务定位，可用中文 |
| 菜单设计与印刷服务 | 实际提供的服务；印刷、配送、翻译等没有提供就不要填写 |
| 案例与优势 | 可核实的作品、链接与案例；没有可以留空 |
| 服务限制 | 报价、交期、配送范围等实际限制；未知的事项明确写需确认 |
| 英文品牌名称 | 由你确认使用的对外名称，系统不会擅自翻译公司名 |
| 英文服务介绍 | 自行填写，或点击“AI 整理英文介绍”核对后采用 |
| 默认发件人／职务 | 真实英文姓名或本人确认的拼音、英文职务；职务可选 |
| 公司官网 | 可选，完整的 http/https 地址 |
| 表达风格 | 专业简洁或自然友好，均避免夸大和无依据承诺 |
| 退出说明 | 默认英文说明可沿用，加入完整客户消息末尾 |

AI 整理不会自动保存。核对英文介绍与中文事实一致后点击“采用英文介绍”，再保存服务资料；英文品牌、真实姓名仍由用户提供。若等待 AI 时修改资料，本次结果不再采用，需重新生成。

“预览英文示例”读取当前表单，使用虚构的 Example Restaurant 演示没有菜单时的询问路径。显示英文主题、正文、署名、退出说明，以及仅供内部使用的中文对照和起草依据；不保存文案、不创建任务、不发送邮件。真实门店的 AI 起草继续使用该门店已核对的菜单及相关证据。

业务成员在 **个人账号 → 我的英文署名** 填写个人英文姓名／职务，管理员也可以在设置页维护自己的署名。留空沿用公司默认值。准备触达、保存跟进草稿时自动带入署名和退出说明，允许临时修改；正在编辑的内容不会被迟到的默认值覆盖。

服务资料保存仍采用版本检查；公司资料更新会使旧 AI 消息需要重新生成并确认。个人署名修改只影响后续起草，不会改写已经生成的文案。授权、准入、内容确认及发送前检查保持生效。页面不自动填入未经确认的真实公司服务、英文品牌或身份。

填写提醒：**英文品牌名称只填简短名称，例如你确认使用的 Xiaodangjia，不要粘贴整段英文服务介绍**。旧误填会在准备触达时提示配置问题，需要回到设置修正后重新打开门店并起草；已有文案不会被自动改写。无餐饮经营证据的学校／机构，不能仅凭名称假定存在咖啡馆或菜单采购需求。

### 创建就绪任务按钮不可用时

按钮中的数字表示已满足创建条件的门店数。为 0 时，在草稿的缺项提示旁直接处理：

- 提示准入规则更新：点击「重新核验准入」，按当前规则重新评估已保存证据；不足时仍显示具体缺项，可补充依据或打开「准入设置」。
- 提示消息未确认：点击「核对消息内容」，核对主题与正文后确认。
- 已在其他位置完成修改：点击「重新检查创建条件」，只读刷新当前状态。

处理后按钮自动更新。创建失败仍保留编辑区；创建任务不会自动发送邮件。模拟验证：`uv run --project apps/api --extra maps-worker python scripts/verify_readiness_ui.py`。

### 全渠道联系条件与准备待办（2026-10-26）

准备区点击 **加入准备待办**，即使没有联系人或消息，也可安排负责人和提醒，并在“触达任务与回复”继续处理。查看或保存普通草稿不会自动加入工作台。移出待办保留草稿及门店资料。

联系方式的 **核验与设置 → 联系条件**，以及准备区、沟通页，都使用同一个表单。按渠道填写真实依据、来源、实际核对日期、下次复核时间；没有资料可保存“待补充依据”。电话需录入 TPS／CTPS 的真实结果；AI 不会代替筛查服务。

**回复客户明确提出的请求**需选择已确认的消息，引用客户请求及回复范围；只对这份回复有效。主动询问菜单仍是主动业务联系，不能当成客户已提出请求。改变回复内容或收件人后需重新核对；平台 API 连接、权限及会话窗口仍在执行时检查。

“AI 补查归属与依据”读取官网事实，并保留表单未保存内容，不推断同意或平台权限。人工允许／禁止记录不由 AI 覆盖。所有条件齐备后创建执行任务；创建本身不发送。

新增迁移 `d176a0010001`。详细设计与当前能力见 [全渠道联系条件](../plan/channel-conditions.md)。

## 2026-10-26 简化准备消息

在门店详情或名单的准备入口选择联系方式，点击 AI 起草，直接编辑主题和正文；编辑自动保存。点击“预览并发送”后，系统集中检查并显示完整邮件。核对后勾选并点击“确认发送”，系统自动建立沟通记录并提交发送，不再单独审批消息或创建就绪任务。

发现缺项时，页面优先展示一个处理入口，其余检查原因折叠；负责人、提醒、历史消息与联系条件在“更多选项”及检查详情内。可选择“稍后处理”保留待办。

人工渠道使用“预览并打开联系入口”，确认后复制内容、打开入口，实际联系后再回填结果。打开入口不算发送成功。API 渠道提交后查看沟通记录的实际结果，未知结果不自动重发。

预览不发送；旧预览在收件人、内容或发件账号变更后不能继续提交。同一草稿重复确认复用原沟通记录。

### 邮件收件人确认（2026-10-26 更新）

邮件准备不再要求先提交联系方式归属原文、公司主体等证据。选择邮箱、核对主题正文后，在最终预览确认收件人即可提交；该确认只绑定本次地址和消息，不会将 AI 未核验结果标记为已核验。拒收、明确禁止联系、无效地址和账号权限仍会阻止发送。Gmail 需已授权，并在设置中开启“允许发送”；批量队列不必开启。

## 手动新增门店（2026-10-26）

在“批次与线索”顶部点击“新增门店”。只有门店名称必填；可填写官网、地区、地址、邮编、联系人、邮箱、电话及社媒地址、备注。

- 默认加入当前名单；清空名单选择后自动创建或复用自己的“手动录入”名单。
- 业务成员新增门店归自己；管理员及销售总监可选择有效负责人。查重只显示自己有权查看的门店。
- 保存前按名称、官网域名及联系方式提示可能重复。可打开已有门店；不同分店可明确选择“仍然新建”，系统不会自动合并。
- “保存并查看”进入详情；“保存并 AI 完善”保存后在后台启动官网及联系方式完善。服务不可用也保留门店，可进入详情稍后继续。
- 菜单可在详情上传或获取，随后使用原有消息准备和沟通流程。新增门店不会自动发送消息。
- 手填官网标记为人工资料，自动补充不直接覆盖。联系人及备注可在详情“来源与历史”查看。
- 当前名单正在处理时不会插入新的门店；可选择自己的手动录入名单，或等待原任务结束。

无需数据库迁移。浏览器模拟验证：`uv run --project apps/api --extra maps-worker python scripts/verify_manual_lead_ui.py`。
