# 欧洲餐厅发现与邮箱/菜单获取的数据来源（截至 2026-09）

> 调研范围：发现（国家/城市/菜系/价位/评分）→ 官网 → 通用商务邮箱 → 菜单 URL/PDF/图片。聚焦 EU + UK。
> 说明：OSM 覆盖率数字为本次（2026-09-25）通过 taginfo API 与 Overpass API 实测，非二手资料。

## 1. Google Places API (New)：字段、SKU 定价与免费额度，~1000–5000 家成本

### Takeaway
Places API (New) 能返回 websiteUri、电话、rating、userRatingCount、priceLevel/priceRange、types、businessStatus，但**不返回 email，也没有菜单 URL 字段**（仅有 menuForChildren、servesVegetarianFood 这类布尔属性）。官网/评分/价位字段落在 Enterprise SKU；3–5 个城市筛 1000–5000 家的 API 费用约 **$0–$100/月**，经济上不是瓶颈，瓶颈在条款（见第 2 节）。

### Cited Findings
- 2025-03 定价改革后的 SKU 与免费月额度（每 SKU 单独计）：Text Search Essentials (IDs Only) 无限免费；Text Search Pro 免费 5,000 次，之后 $32/1000；Text Search Enterprise 免费 1,000 次，$35/1000；Text Search Enterprise + Atmosphere 免费 1,000 次，$40/1000 — [Google Maps Platform Pricing](https://developers.google.com/maps/billing-and-pricing/pricing)
- Nearby Search：Pro 免费 5,000，$32/1000；Enterprise 免费 1,000，$35/1000；Enterprise + Atmosphere 免费 1,000，$40/1000 — [Pricing](https://developers.google.com/maps/billing-and-pricing/pricing)
- Place Details：Essentials (IDs Only) 无限免费；Essentials 免费 10,000，$5/1000；Pro 免费 5,000，$17/1000；Enterprise 免费 1,000，$20/1000；Enterprise + Atmosphere 免费 1,000，$25/1000 — [Pricing](https://developers.google.com/maps/billing-and-pricing/pricing)
- 字段所属 SKU：websiteUri、nationalPhoneNumber、rating、userRatingCount、priceLevel、priceRange = Enterprise；businessStatus = Pro；types = Essentials；servesVegetarianFood、menuForChildren = Enterprise + Atmosphere；**文档中没有 email 字段或菜单链接字段** — [Place Data Fields](https://developers.google.com/maps/documentation/places/web-service/data-fields)
- 计费按 FieldMask 中"最高级"字段决定 SKU（websiteUri/rating/userRatingCount/priceLevel/phone 会把请求推到 Enterprise）— [Pricing](https://developers.google.com/maps/billing-and-pricing/pricing)

### Inferences
- 成本估算（单月、单个结算账户）：
  - 方案 A：Text Search 直接带 Enterprise 字段（websiteUri,rating,userRatingCount,priceLevel,businessStatus,types）。Text Search 每页最多 20 条、单查询最多约 60 条（按 Google 文档的 pageSize/pageToken 机制，需再核实），为覆盖城市需按"城市×区/网格×菜系"切分查询。5000 家、考虑 2–3 倍重叠 ≈ 500–1,500 次请求 → 前 1,000 次免费，额外 ≤500 次 × $35/1000 ≈ **$0–$18**。
  - 方案 B：Text Search IDs Only（免费）拿 place_id → Place Details Enterprise 逐个补字段。1000 家 ≈ 免费额度内 $0；5000 家 ≈ (5000−1000)×$20/1000 = **$80**。
  - 结论：API 费用对 1000–5000 家筛选规模可忽略；真正成本在后续官网抓取/邮箱验证/人工复核。
- openingDate 等"开业时间"字段在所查数据字段页中未见（未能确认存在）。

### Gaps
- 未能抓取到 Text Search (New) 单查询 60 条上限的原文页面，建议实施前在 https://developers.google.com/maps/documentation/places/web-service/text-search 核实。
- 未确认是否有 openingDate 字段。

## 2. Google Maps Platform 条款：缓存/存储、能否用于 CRM/线索库

### Takeaway
**把 Places 数据（官网、电话、评分等）存进自建 CRM/线索库，在条款上基本不被允许**：只有 place_id 可无限期存储；其他内容禁止预取、缓存、存储（例外很窄）。EEA 结算账户自 2025-07-08 起适用独立的 EEA 条款，且更进一步禁止把 Places 内容与任何地图一起展示。可行的合规做法：Google 只用来"实时发现 + 存 place_id"，官网/邮箱/菜单等由自己从餐厅官网（公开来源）重新采集并存储。

### Cited Findings
- "place ID ... is exempt from the caching restrictions. You can therefore store place ID values indefinitely"；其他内容不得 pre-fetch/cache/store（除允许的例外）— [Places API Policies](https://developers.google.com/maps/documentation/places/web-service/policies)
- 在无 Google 地图的情况下展示 Places 数据必须显示 Google 标志并遵守署名规范 — [Places API Policies](https://developers.google.com/maps/documentation/places/web-service/policies)
- EEA：自 2025-07-08 起，结算地址在 EEA 的项目适用 "Google Maps Platform EEA Terms of Service" 与 EEA Service Specific Terms — [EEA FAQ](https://developers.google.com/maps/comms/eea/faq)；[EEA ToS](https://cloud.google.com/terms/maps-platform/eea)
- EEA 条款：客户不得缓存 Google Maps Content，除非 Service Specific Terms 明示允许；Google ID 值可缓存；POI Counts 可缓存 30 天仅用于计算 — [EEA Service Specific Terms（存档 2025-11-18）](https://cloud.google.com/archive/terms/maps-platform/eea/maps-service-terms-20251118)
- EEA：除 lat/lng 和 place_id 外，Places API 内容不得与任何地图（包括 Google 地图）一起使用；需要地图展示应改用 Places UI Kit — [EEA Places adjustments](https://developers.google.com/maps/comms/eea/places)；[EEA FAQ](https://developers.google.com/maps/comms/eea/faq)

### Inferences
- 用 Places 数据建"线索数据库/CRM"与"禁止缓存/存储内容"原则直接冲突；全球版 ToS 3.2.3 条亦有"No Scraping / No Caching / No Creating Content From Google Maps Content"的禁止条款（本次未能抓到原文全文，依据为对条款结构的既有了解，需人工核对 https://cloud.google.com/maps-platform/terms）。
- Outscraper/Apify 等"Google Maps 抓取器"本质是绕过 API 抓取 Google Maps，违反 Google 条款的"No Scraping"精神；使用者自身不是 Google 的合同方时风险主要落在工具方，但数据来源合规性仍存疑，商用时需自担风险。
- 合规折中路径：Google 返回的 websiteUri 只作为"指针"，立即访问官网并从官网（餐厅自行公开）提取网址/邮箱/菜单，CRM 中只存 place_id + 自采数据。这一做法的边界（websiteUri 本身是否算"Google Maps Content"）存在灰度，建议法务确认。

### Gaps
- 未取得全球版 ToS 3.2.3 与 EEA 版限制条款的逐字原文（页面过长被截断）。
- 未找到 Google 对"lead generation / CRM"用例的官方明确表述。

## 3. OpenStreetMap / Overpass：主要城市覆盖率与 ODbL 义务

### Takeaway
OSM 免费、可存储、可商用（需遵守 ODbL），菜系（cuisine）覆盖较好，但**官网覆盖 16%–66%、邮箱仅 4%–17%、菜单链接 <10%（都柏林例外 19%）**，且无评分/价位数据。适合作为免费种子名单与交叉去重来源，不能单独满足"评分/价位"筛选。德国、荷兰城市的覆盖明显优于南欧。

### Cited Findings
- 全球 amenity=restaurant 对象 1,620,020 个（节点 1,323,009，ways 295,177）；组合标签占比：cuisine 48.3%，phone 23.1%，website 20.1%（另 contact:website 2.0%），opening_hours 23.3%，email 4.2%，contact:facebook 2.9% — [taginfo amenity=restaurant](https://taginfo.openstreetmap.org/tags/amenity=restaurant)（数据截至 2026-09-25，API 实测）
- 各城市实测（Overpass，website 含 contact:website，email 含 contact:email，menu 含 menu/website:menu/menu:url）— [Overpass API](https://overpass-api.de/)：

- Overpass 公共实例在高峰期频繁报 "server is probably too busy"，且未带 User-Agent 的请求返回 HTTP 406（本次实测）— [overpass-api.de](https://overpass-api.de/)
- OSM 数据以 ODbL 授权（Overpass 返回中亦声明 "made available under ODbL"）— [OSM Copyright](https://www.openstreetmap.org/copyright)

### Inferences
- "Dublin" 行政区域仅指都柏林市（873 家），明显小于实际都会区；伦敦为 Greater London。城市边界选择会显著影响数字。
- OSM 餐厅总数普遍低于 Google（Google 通常包含更多小店/外卖店），OSM 数据可能遗漏新开店、包含已关闭店（新鲜度依赖志愿者）。
- ODbL 义务（按 osm.org/copyright 的通行解读）：公开使用需署名 "© OpenStreetMap contributors"；若公开分发"衍生数据库"需以 ODbL 共享。仅内部 CRM 使用、不对外发布数据库，一般不触发共享义务；向客户交付名单则可能触发。建议仅把 OSM 作为种子，邮箱/菜单以官网自采为准。
- 大规模/批量查询建议自建 Overpass 或下载 Geofabrik 国家级 .pbf 本地过滤，避免公共实例限流。

### Gaps
- München 的 Overpass 查询因服务器繁忙未在截稿前完成。
- 未与 Google 对同城做总数对比，OSM 相对 Google 的召回率未量化。

## 4. 替代数据源：Foursquare、Yelp、Tripadvisor、TheFork、Outscraper/Apify、商业登记、B2B 数据商

### Takeaway
Foursquare 是少数**官方 API 字段含 email** 且按调用计费的来源（Pro 字段含 tel/website/email，rating/price 属 Premium），可作为 Google 的合规替代；Yelp 在欧洲覆盖有限且已取消免费层（最低 $229/月）；Tripadvisor 有每月 5,000 次免费调用但条款强调署名展示、禁止爬取；Outscraper 类抓取器最便宜（约 $3/1000 条，加邮箱 $3/1000）但依赖抓取 Google Maps，条款风险高。

### Cited Findings
- Foursquare：遗留 V3 端点于 2026-05-15 废弃；2026-06-01 起新价：Pro 端点 $15/1000（每月 500 次免费），>100k 降至 $12，>500k 降至 $9；Premium 端点 $18.75→$11.25/1000；免费额度页面存在"500 次"与"最多 10,000 次"的矛盾表述 — [openplacesapi.com 对比页](https://openplacesapi.com/compare/foursquare-places-api)（二手汇总）；官方参考 [Foursquare Upcoming Changes](https://docs.foursquare.com/developer/reference/upcoming-changes)、[Foursquare Pricing](https://foursquare.com/pricing/)
- Foursquare 字段分级：Pro 含 tel、website、email（"Primary contact email address of organization, if available"）、date_closed、facebook_id/instagram/twitter；Premium 增加 hours、rating(0–10)、price（Cheap/Moderate/Expensive/Very Expensive）；无菜单字段 — [Foursquare Places Pro and Premium](https://docs.foursquare.com/data-products/docs/places-pro-and-premium)
- Yelp Places API（原 Fusion）：Base $229/月（约 $5.91/1000）、Enhanced $299/月（$6.57/1000）、Premium $643/月（$14.13/1000），均含 5,000 次免费试用；Insights API 按地点 $0.04–$0.08 — [Yelp Data Licensing Pricing](https://business.yelp.com/data/resources/pricing/)
- Yelp 已结束免费访问、全部转为付费（2024 年引发开发者不满）— [TechCrunch 2024-08-02](https://techcrunch.com/2024/08/02/yelps-lack-of-transparency-around-api-charges-angers-developers/)
- Yelp 月调用 >150,000 需联系销售 — [Yelp Plans](https://docs.developer.yelp.com/docs/plans)
- Tripadvisor Content API：每月前 5,000 次免费（需绑卡），搜索 API 每日上限 10,000 次，超出按阶梯计费；必须按展示规范署名（logo、气泡评分）— [Tripadvisor Content API FAQ](https://tripadvisor-content-api.readme.io/reference/faq)；[Rate Limits](https://tripadvisor-content-api.readme.io/reference/rate-limits)
- Tripadvisor 旧版与 Terra 条款均禁止 API 之外的机器人/爬虫自动提取；遗留 API 限制 AI 用途仅限内部测试 — [Vorp Labs 分析](https://vorplabs.com/agent-tools/tripadvisor-content-api)（二手）；[API Master Terms](https://tripadvisor-content-api.readme.io/reference/api-master-terms-new)
- Outscraper：前 500 条免费，501–100,000 条 $3/1000，>100,000 条 $1/1000；Emails & Contacts 抓取 +$3/1000，邮箱验证 +$3/1000；按量付费无月费 — [Outscraper 官方定价说明](https://outscraper.com/google-maps-scraper-pricing-enrichment-cost/)；[Outscraper Pricing](https://outscraper.com/pricing/)

### Inferences
- 1000–5000 家成本对比（粗估）：Foursquare Premium ≈ $19–$94（未扣免费额度）；Yelp 最低 $229/月（按月订阅，小规模不划算）；Outscraper 含邮箱+验证 ≈ $9/1000 → $9–$45；Google 官方 API ≈ $0–$80（见第 1 节）。
- Foursquare 条款中关于存储/再分发的限制本次未查到，需要阅读其 API 许可条款后再确定能否入 CRM。
- TheFork（Tripadvisor 旗下）面向餐厅/合作伙伴有 B2B API，但本次未找到公开的数据发现类 API 或价格，不应作为发现来源假设。
- 商业登记：Companies House（英国）提供免费 API，可按 SIC 56101（Licensed restaurants）/56102（Unlicensed restaurants）检索公司，但登记的是法律实体与注册地址（常为会计师地址），通常无官网/邮箱；荷兰 KvK、德国 Handelsregister 类似且多数收费/限制批量查询。适合用于核实主体、找决策人，不适合作为发现来源。（本条为推断，未在本次检索中取得原文来源）
- B2B 数据商（如 Apollo、Cognism、Dealfront/Echobot 等）对小型独立餐厅覆盖通常较弱，本次未取得价格/覆盖数据。

### Gaps
- TheFork、Deliveroo/Uber Eats/Just Eat/Lieferando 无公开可用于发现的数据 API（未找到来源）。
- Apify 各 Google Maps actor 的具体价格与条款本次未核实。
- Foursquare/Yelp 在具体欧洲城市的覆盖率无公开数字。

## 5. 餐厅拥有官网、在线菜单（HTML/PDF/图片/仅外卖平台）、公开邮箱的比例

### Takeaway
没有找到针对欧洲、近两年的权威统计。可用的代理指标是本次 OSM 实测：主要城市 16%–66% 的餐厅登记了官网，4%–17% 登记了邮箱。美国旧研究显示独立餐厅过半无官网、不到 40% 在官网展示菜单。实际 pipeline 中应预期：有官网 ≈ 50–70%（Google 数据通常高于 OSM），其中能直接解析出菜单的更少，PDF/图片菜单占比不低，需 OCR/多模态解析。

### Cited Findings
- 独立餐厅中超过一半没有网站，不到 40% 在网站上展示菜单；仅约 1/20 独立餐厅有移动版网站（2012 年美国研究，已过时）— [TechCrunch](https://techcrunch.com/?p=542786)
- 77% 的食客在前往前会查看餐厅网站（美国调查）— [Restaurant Dive](https://www.restaurantdive.com/news/77-of-diners-visit-restaurant-websites-before-going-survey-finds/562008/)
- 约 30% 的受访者因"菜单难以阅读"而放弃前往某餐厅；33% 因网站难用（美国）— [PR Newswire 调查](https://www.prnewswire.com/news-releases/survey-nearly-70-of-us-diners-say-a-restaurants-website-has-discouraged-them-from-visiting-300909229.html)
- 65% 的食客直接通过餐厅官网预订（Toast 2025 数据，美国）— [Toast](https://pos.toasttab.com/blog/data/restaurant-wait-times-and-reservations-data)
- OSM 实测邮箱/菜单链接占比见第 3 节表格 — [taginfo](https://taginfo.openstreetmap.org/tags/amenity=restaurant)

### Inferences
- 菜单格式分布（HTML vs PDF vs 图片 vs 仅外卖平台）没有可引用的统计；建议在试点城市抽样 100–200 家官网人工标注，作为 pipeline 设计依据。
- 大量小型餐厅（尤其南欧）只有 Instagram/Facebook 页或只在 Deliveroo/Uber Eats/Just Eat/Lieferando 上有菜单；外卖平台条款普遍禁止抓取，应只存链接不抓内容。

### Gaps
- 欧洲（EU+UK）近年的"餐厅有官网/在线菜单/公开邮箱"比例统计：未找到可靠来源。
- 菜单文件格式分布：未找到数据。

## 6. 从官网找邮箱：联系页、mailto、德奥 Impressum；验证服务与成本

### Takeaway
德国（及奥地利）是邮箱获取最友好的市场：商业网站必须在 Impressum 中提供电子邮件地址（§5 DDG，2024-05-14 起取代 TMG）。其他国家依赖联系页/mailto/页脚，也受 EU 电子商务指令 2000/31/EC 第 5 条（需公开电子邮件地址）约束，但执行力度弱。验证成本约 $3–$20/1000 封，对 1000–5000 个地址仅需几十美元。

### Cited Findings
- §5 DDG 要求提供"能迅速电子联系和直接沟通的信息，包括电子邮件地址"；DDG 于 2024-05-14 生效，基本沿用 TMG §5 — [§5 DDG 原文](https://www.gesetze-im-internet.de/ddg/__5.html)；[IHK Chemnitz](https://www.ihk.de/chemnitz/recht-und-steuern/rechtsinformationen/internetrecht/pflichtangaben-im-internet-die-impressumspflicht-4401580)
- 仅提供联系表单不足以满足 Impressum 要求（BGH 判例相关解读）— [zerodox](https://zerodox.de/blog/was-ist-5-tmg-impressumspflicht)
- NeverBounce：入门 $8/1000（$0.008/封），大量时降至 $0.003–0.004；额度 12 个月过期 — [NeverBounce Pricing](https://www.neverbounce.com/pricing)；[Cleanlist 汇总](https://www.cleanlist.ai/blog/2026-07-17-neverbounce-pricing-guide)
- ZeroBounce：最低购买 2,000 credits 为 $39（$0.0195/封），100 万以上降至 $0.0032；credits 不过期 — [Bouncer 汇总](https://www.usebouncer.com/zerobounce-pricing/)
- Outscraper 附带邮箱验证 $3/1000 — [Outscraper](https://outscraper.com/google-maps-scraper-pricing-enrichment-cost/)

### Inferences
- 邮箱提取顺序建议：首页/页脚 mailto → /kontakt /contact /impressum /imprint /mentions-legales /aviso-legal /privacy（隐私政策常写数据控制者邮箱）→ 结构化数据（schema.org Restaurant 的 email）→ Facebook 页。注意混淆写法（"info [at]"）与图片邮箱。
- 验证预算：5000 个邮箱 × NeverBounce $8/1000 ≈ $40；ZeroBounce ≈ $98（按 $0.0195）。餐厅域名常为 catch-all（Wix/Squarespace/本地主机商），验证结果中 "unknown/catch-all" 占比可能较高。
- 合规提醒：公开的通用商务邮箱（info@）可用于 B2B 联系，但 GDPR（个人姓名邮箱属个人数据）及各国 ePrivacy 规则（如德国 UWG §7 对 B2B 冷邮件也要求推定同意，较严）需单独评估；德国市场邮箱最易获取但冷邮件法律风险也最高。

### Gaps
- 未找到"餐厅官网中可提取到邮箱的比例"统计；OSM email 标签（4%–17%）只是下限代理。

## 7. 风险：反爬、robots.txt、数据新鲜度、去重

### Takeaway
主要风险在条款与数据质量，而非技术：Google/Tripadvisor/外卖平台条款禁止抓取；公共 Overpass 限流；OSM 与商家信息存在过期；多源合并需以 place_id + 域名 + 电话 + 规范化地址去重。

### Cited Findings
- Tripadvisor 禁止 API 之外的机器人/爬虫 — [Vorp Labs](https://vorplabs.com/agent-tools/tripadvisor-content-api)
- Google：除 place_id 外不得缓存/存储 Places 内容 — [Places API Policies](https://developers.google.com/maps/documentation/places/web-service/policies)
- Overpass 公共实例繁忙时直接拒绝请求；无 UA 请求返回 406（本次实测）— [overpass-api.de](https://overpass-api.de/)
- Foursquare 提供 date_closed 字段可用于过滤已关闭场所 — [Foursquare Pro/Premium](https://docs.foursquare.com/data-products/docs/places-pro-and-premium)
- Google businessStatus（Pro SKU）可过滤 CLOSED_PERMANENTLY — [Place Data Fields](https://developers.google.com/maps/documentation/places/web-service/data-fields)

### Inferences
- 餐厅官网本身大多是小站点，抓取量小（每站 3–6 页），遵守 robots.txt、限速（如 ≤1 req/s/域名）、明确 UA 即可，反爬风险低；Cloudflare 保护的连锁站点可能需要无头浏览器。
- 新鲜度：Google 保留 place_id，按需实时刷新（成本低）；自采邮箱/菜单建议 90 天重验。
- 去重键：Google place_id ↔ OSM（通过名称+坐标 50m 内匹配）↔ 官网注册域名（连锁店同域名需按分店拆分）。
